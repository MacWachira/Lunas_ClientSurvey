# LUNAS Survey and Loyalty API

Production-oriented Express/PostgreSQL backend for the existing Vercel frontend.

## What it provides

- Atomic survey creation and loyalty awarding in one PostgreSQL transaction.
- Exactly one automatic 10-point award per customer and visit date.
- Idempotency keys, so browser retries do not duplicate surveys or points.
- Immutable loyalty transaction ledger for earnings and manual adjustments.
- Server-side admin authentication with bcrypt password hashes and four-hour signed tokens.
- Strict request validation, exact-origin CORS, rate limits, security headers, request logs, and graceful shutdown.
- Searchable loyalty members, balances, rewarded visit counts, survey data, and transaction history.
- A health endpoint and repeatable SQL migrations for Render.

## Deploy to Render with the Blueprint

1. Commit and push this repository to GitHub.
2. Sign in to Render and select **New > Blueprint**.
3. Connect `MacWachira/Lunas_ClientSurvey`. Render reads the root `render.yaml` and proposes one web service plus one PostgreSQL database.
4. Enter the prompted secret values:
   - `ALLOWED_ORIGINS`: the exact Vercel URL, for example `https://your-project.vercel.app`. Add custom domains separated by commas.
   - `ADMIN_EMAIL`: the email used to open the analytics dashboard.
   - `ADMIN_PASSWORD`: a unique password of at least 12 characters. Use a password manager.
5. Create the Blueprint. `JWT_SECRET` is generated by Render and `DATABASE_URL` is linked automatically to the database.
6. Wait for `/health` to return `{"status":"ok","database":"connected"}` at your Render service URL.

The service runs migrations before every start. Migrations are recorded and safe to rerun. The server binds to Render's `PORT` on `0.0.0.0`.

> The Blueprint uses free plans for an easy first deployment. Render free web services can sleep after inactivity, and free databases are unsuitable for a business production workload. Upgrade both resources before relying on this for day-to-day operations and enable PostgreSQL backups.

## Connect the Vercel frontend

1. Copy the Render web-service URL, such as `https://lunas-client-survey-api.onrender.com`.
2. Put it in the repository root `config.js`:

   ```js
   window.LUNAS_API_URL = 'https://lunas-client-survey-api.onrender.com';
   ```

3. Ensure the exact Vercel URL is in Render's `ALLOWED_ORIGINS` variable. Do not use `*`.
4. Commit and push. Vercel will redeploy the frontend.
5. Submit one test survey, then open **Analytics Dashboard**, log in using `ADMIN_EMAIL` and `ADMIN_PASSWORD`, and open **Loyalty Members**.

## Import the existing Google Sheet records once

Run from the `backend` directory after the Render API is live:

```bash
LEGACY_GOOGLE_SCRIPT_URL='https://script.google.com/macros/s/YOUR_ID/exec' \
BACKEND_API_URL='https://YOUR-SERVICE.onrender.com' \
npm run import:legacy
```

The importer derives stable idempotency keys, so rerunning it does not duplicate the old rows or their awards. The current legacy endpoint does not return client names or old loyalty fields; imported customers therefore use the phone number as their durable identity until their next named survey.

## Local development

1. Create a PostgreSQL database.
2. Copy `.env.example` to `.env` and replace every placeholder.
3. Run:

```bash
npm install
npm run migrate
npm run dev
```

Test with `npm test`. Never commit `.env` or real credentials.

## Main endpoints

- `GET /health`
- `POST /api/v1/surveys` — public, validated and rate-limited
- `POST /api/v1/auth/login` — admin login
- `GET /api/v1/auth/me` — validate an admin token
- `GET /api/v1/admin/surveys` — admin survey feed
- `GET /api/v1/admin/loyalty/members` — customer balances
- `GET /api/v1/admin/loyalty/transactions` — points audit ledger
- `POST /api/v1/admin/loyalty/members/:customerId/adjustments` — audited credit or debit

Admin endpoints require `Authorization: Bearer <token>`.
